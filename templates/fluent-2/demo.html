01 — Chrome & layering

Three grays and a hairline

The window stacks mica (surface, #f5f5f5), a content layer (surface-raised, #fbfbfb) and white cards, every step separated by an #e5e5e5 hairline. Shadows stay shallow — the stroke and the gray ladder do the depth work; acrylic is reserved for the surfaces that float over content, like the Sort flyout on the cover.

mica — surface the window base
content layer — surface-raised where lists live
card cards and inputs, hairline stroke, no shadow
Acrylic — rgb(249 249 249 / 0.85) + blur(20px). It floats over content, carries shadow-md and a hairline, and never appears on cards or the page itself.

Window anatomy: app glyph and title left, caption buttons right with close hovering red; one vertical hairline spines the command bar, address bar and content.

02 — Color roles

One calm blue, a teal second voice

Fluent blue #0f6cbd fills the single primary command and draws focus and selection. The pinned second voice is teal #038387 — chosen over the lighter brand variant #2899f5, which reads as the same blue one step brighter and adds no second meaning. Error red #c50f1f stays serious and undecorated.

Window chrome never takes color: title bar, command bar and nav pane stay gray; color marks content and state only.

03 — Controls

8px corners, subtle by default

Buttons come in accent, standard (white with a #d1d1d1 stroke) and subtle (a soft gray fill). Focus draws a 2px blue underline at the input's bottom edge. The toggle is a pill with a square-ish thumb — dark on gray when off, white on blue when on.

One accent-filled command per view; checkboxes and radios tint blue only when selected; destructive actions use error red text or fill, alone.

04 — Typography

Segoe rhythm, weight 600, 14px body

The stack starts at Segoe UI Variable and falls back through the system sans. Body and controls run 14px; captions 12px; page titles 28px and section titles 20px at weight 600. Emphasis is weight, never a color change.

05 — Mobile

The window becomes a page; the pane becomes a bar

On small screens the three-gray stack survives but the furniture re-arranges: the nav pane folds away, the command bar scrolls horizontally, and a bottom bar takes over navigation. Targets grow; hover gives way to press.

06 — Off-style, for contrast

What breaks the Windows calm

Projects
Window title, 15px rows, a heavy diffuse shadow and 12px corners — macOS chrome on a Windows document.
Traffic lights on the left, vibrancy gray, a large soft window shadow and oversized type: every platform cue points the wrong way. Windows chrome is gray, caption buttons live right, shadows stay shallow, corners stay 8px.

See the cover window: same content, correct chrome — title left, ─ ▢ ✕ right, hairline-spined command and address bars, flyout as the only floating surface.

The chrome reads as one quiet instrument panel: three grays, one hairline, one blue command, and nothing colored that isn't content.
A "card" built from 35% acrylic + blur(6px) — blurry, low-contrast, and floating over nothing.
Acrylic on persistent content is noise: it muddies text, wastes the blur budget and feels like a translucent sticker over the content it should sit above.
A real card: white fill, hairline stroke, zero shadow — content that sits in the layer stack, not over it.
Cards are opaque and stroke-separated; acrylic is only for the flyout that floats above them. Layering stays legible because each material has one job.

Also out: pill buttons, corners above 8px on controls, colored window chrome, more than one accent-filled command per view, and shadows doing the hairline's job.
