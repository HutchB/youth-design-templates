The console folds to one column

A terminal is already single-column, so the phone changes arithmetic, not structure: the measure shortens, lines wrap like a narrow tty, and keys become thumb-sized buttons pinned under the session.

  • Measure shrinks, wrap winsThe 80-char console becomes a narrow tty: output wraps mid-token with word-break, exactly as a real terminal does. Tables keep only service and status; node and delta columns drop.
  • Keys become buttonsThe `[Y/n]` prompt renders as two bordered mono buttons pinned under the session, 44px+ tall. Hover-fill states move to :active — touch has no hover.
  • Cursor stays a blockThe blinking block caret survives at 8×16px. It is the system's only animation and the clearest "this is a terminal" signal on a phone.
  • Type floor 13pxBase drops from 15px to 13px mono — never smaller, and never proportional. Status badges keep their bracket glyph so they survive wrap.
  • Bloom halvesGlow radii cut roughly in half on small screens so dense text doesn't smear; scanlines stay full-bleed at the same opacity.
  • One pane per screenPanels stack as full-width bordered boxes with 1px hairlines; no side-by-side panes, no split view — a tty has one viewport.

03

What breaks the phosphor

Soft app card

12px rounded corners, sans-serif stack, gray-on-gray hierarchy, blurred drop shadow, pastel status pills.

Wrong typeface, wrong corners, wrong depth. On the glass this reads as a web page wearing a terminal costume.
Same content, on-style

square corners, mono stack, dimmed-green hierarchy, 1px hairlines, bracket badges.

Text is the interface; brightness is the hierarchy. That is the whole machine — nothing else is needed.

Also out: gray neutrals, cast shadows, any radius above 0, non-mono display type, gradients beyond the scanline overlay, and images-as-chrome — if the CRT could not have drawn it, it does not ship.
